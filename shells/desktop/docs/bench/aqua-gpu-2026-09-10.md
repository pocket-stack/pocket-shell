# Native Aqua GPU drag check — 2026-09-10

The desktop host now executes the shared DrawList through the existing
`pocket-ui-wgpu` and `pocket3d::gpu` APIs. No new crate is required.
The browser keeps the Rust software rasterizer; applications and themes use
the same contracts.

## Native results

Apple M3 Max, 2× raster density, release builds, scripted Notepad title-bar
drag. The default 800×600 size is the primary acceptance case.
Each complete drag trace contains 340 measured ticks. CPU figures below are
means across complete runs; they exclude GPU execution time.

| Path | Logical viewport | Draw/submit CPU | Present CPU | Captured trajectory delay estimate |
|---|---|---:|---:|---:|
| PR #10 software baseline | 800×600 | 7.3–7.5 ms | 6.7–6.9 ms | 17–19 ms |
| Existing wgpu backend, two runs | 800×600 | 0.23 ms | 0.10–0.15 ms | 10.8–11.4 ms |
| PR #10 software baseline | 1400×850 | 10.4–10.5 ms | 16.1–16.2 ms | 31–32 ms |
| Existing wgpu backend, one run | 1400×850 | 0.24 ms | 0.20 ms | about 12 ms |

The capture estimates fit horizontal window positions from ScreenCaptureKit
against tick-start timestamps. They exclude physical input delivery and panel
scanout; capture sampling gives several milliseconds of uncertainty. The earlier
main/gpui comparison occupied a 7–11 ms range with this method. These data do
not establish identical physical latency to main or claim a higher panel FPS.

The capture replay uses the same compiled PR #10 packages, density, 360-step
trajectory and ticks 131–470 as the software baseline. An isolated diagnostic
host filters external pointer/focus input during scripted replay. The production
host retains normal input handling. An interrupted first GPU trial and a later
main replay with invalid trajectory tracking are excluded from this table.

The final production binary also passed the checked-in `benchmark:drag` tape
with 340 presented frames and p95 CPU budgets of 16.7 ms for worker work,
3 ms for render submission and 3 ms for presentation submission.
[Machine, artifact hashes and distributions](aqua-gpu-2026-09-10.json) identify
that run. Raw traces and capture CSVs are retained locally under
`.pocket/bench/aqua-drag-2026-09-10/` and `.pocket/bench/drag/`.

## Checks

- Metal readback: 1×/2× rectangles, gradients, triangles, textured triangles,
  glyphs, image formats, atlas replacement, texture updates, stale handles,
  surface painter order, clipping and missing-surface fallback; sRGB overlay
  behavior remains covered. Fixtures permit zero or one byte of channel error.
- GPU frame leases: bounded targets, target reuse and resize while old frames
  remain leased. Output reservation precedes GPU submission under backpressure.
- Native Aqua first paint and drag; Hero open, close and reopen with a rendered
  child surface. Product System UI/WASM/text checks, core tests and host tests
  passed; renderer and host Clippy/rustfmt checks passed.
- Vita Hero VPK and 3DS demo 3DSX built. The 3DS retry selected the pinned nightly
  rustc after the initial environment resolved a stable compiler. No wgpu
  dependency enters either handheld host. These are build checks, not physical
  Vita/3DS display or performance acceptance.

## Repeat

```sh
bun run desktop build
bun run desktop benchmark:drag --max-work-ms=16.7 --max-render-ms=3 --max-present-ms=3
```

Keep the native window focused. CPU budgets are specific to the acceptance
machine. `--trace-frames` can also be passed to the host with another input tape.
